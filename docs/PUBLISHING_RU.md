# Подготовка QA_max_cut_lib к публичному релизу

## Собрать документацию на текущем коммите

Этот комплект подготовлен для API `0.1.0rc2`. Перенеси его в отдельную ветку
актуального проекта и начни с запуска примера. Если API или поведение
изменились, обнови пример, числа и формулы по той версии, которая пойдёт в
релиз. В `README.md` оставь только возможности, проверенные на этом коммите.

| Файл | Роль |
| --- | --- |
| `README.md` | Первая страница репозитория, установка и результат примера |
| `examples/public_quickstart.py` | Воспроизводимый расчёт и источник иллюстрации |
| `docs/weighted_max_cut.rst` | Научная глава с выводом и эталонными проверками |
| `docs/_static/signed-max-cut.svg` | Граф с весами и распределение значений разреза |

Сохрани из действующего README сведения об авторах и ссылки на проверенные
возможности релиза. В `docs/index.rst` добавь `weighted_max_cut` в существующий
`toctree`. После запуска примера пересобери рисунок и Sphinx.

```bash
python -m pip install ".[cpu,docs]"
python examples/public_quickstart.py --figure docs/_static/signed-max-cut.svg
python -m sphinx -W -b html docs docs/_build/html
```

В корне Sphinx выведи путь читателя от установки к первому результату и
научному объяснению. Добавь ссылки на исполняемые ноутбуки текущей версии,
руководство по выбору алгоритма и справочник API. Начни каждую главу с задачи
читателя. Справочные параметры держи рядом с API, выводы и ограничения
алгоритмов — в научных главах.

## Проверить научные утверждения

Для каждого метода зафиксируй задачу и ограничения на вход, соглашение о
знаках, физическую модель, критерий обучения, способ выбора разреза и
масштаб вычислений. Дай малый пример с аналитическим ответом или перебором,
ссылку на первоисточник и конфигурацию для повторения. Сопоставляй методы на
одних и тех же графах, явно указывай вычислительный бюджет, аппаратную
среду и разброс по независимым запускам. Отдельно показывай вес выбранного
разреза, ожидаемый вес и вероятность достичь заданного качества.

Для этой главы три удобные контрольные точки:

1. Одно ребро. Проверить знак энергии, амплитуды, ожидаемый разрез и
   коррелятор по аналитической формуле.
2. Граф со знаковыми весами. Сверить распределение из симулятора с
   перебором базисных состояний и проверить возвращённое разбиение.
3. Редукция. Перебрать допустимые спины для обоих знаков ограничения и
   проверить постоянное смещение на каждом разбиении. Для релиза с
   рекурсивным солвером повторить проверку через его публичный API.

## Открыть проверенную версию

1. Проверь исходники, историю Git, зависимости и права на материалы,
   которые войдут в публичную историю. Исключи секреты, локальные
   окружения и случайные результаты экспериментов. Согласуй лицензию
   проекта и добавь `LICENSE`. Заполни `CITATION.cff` по подтверждённым
   именам авторов, версии и URL репозитория.
2. В CI собери wheel, установи его в чистом окружении и запусти тесты и
   быстрый пример вне каталога исходников. Собирай Sphinx с `-W` из той
   же версии. Проверь заявленные платформы и профили установки, а также
   ссылку на документацию, формулы и мобильный вид главной страницы.
3. Отправь согласованную историю в выбранный GitHub-репозиторий. После
   успешного CI опубликуй Sphinx через GitHub Pages, свяжи README с
   сайтом и выпусти тег и GitHub Release для проверенного коммита.
   Для первого предварительного выпуска используй версию, согласованную
   с метаданными wheel. Если нужен PyPI, проверяй его отдельным
   установочным сценарием.

## Проверка этого комплекта

Windows 10, Python 3.12.14, установленный wheel QA_max_cut_lib 0.1.0rc2,
NumPy 2.5.4 и SciPy 1.18.1. Пример запущен вне исходников пакета.
Для одного ребра вектор состояния, ожидаемый вес и коррелятор сверены
с матричной экспонентой для трёх наборов параметров, включая
отрицательный вес. Формула смещения редукции проверена перебором
для всех допустимых спинов примера. Формула бюджета шотов проверена
для одного и двух слоёв. Глава собрана вместе с действующим справочником
Sphinx 9.1.1 с флагом `-W`.
