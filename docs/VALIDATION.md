# Проверка сборки 0.1.0a1

Дата: 1 ноября 2026. Проверяется первый рабочий CPU-этап, а не все возможности целевой архитектуры.

## Установка и автоматические проверки

Собран wheel `qa_max_cut_lib-0.1.0a1-py3-none-any.whl`; установлен в отдельный каталог без ссылки на `src`. Автоматические проверки и оба учебных сценария используют именно установленный wheel. Выполнено **42 проверки**. Справочник Sphinx/numpydoc собран с `-W` без предупреждений; готовые HTML-страницы находятся в `docs/_build/html`.

Проверены:

- ExactCPU против независимого перебора всех спиновых назначений: знаковые веса, исходные метки с пропусками, изолированные вершины, максимум, минимум и вырождение.
- QAOA против независимого плотного матричного экспоненцирования для p=1 и p=2: знак H_E=−C, порядок слоёв и битов.
- Аналитический граф из одного ребра: ожидаемая энергия −1 при проверочных углах и корреляция −1.
- Пять критериев на известных распределениях, дробная граничная масса CVaR, независимый расчёт Best-of-K и устойчивое вычисление Gibbs.
- Обучение, обе точности состояния, строгий общий бюджет шотов, повторное создание RNG из seed, независимость сохранённой записи от последующих запусков и изменений графа.
- JSON/complex/ndarray/NPY, относительные ссылки, оба режима savedir, конфликт дополнительного файла и одновременные экспорты в одно имя.
- Все девять сочетаний уровней report/logs, отсутствие запуска при импорте, CLI обоих модулей, явное отклонение пока не реализованных режимов.
- Статические графики и восстановление глобальной темы, подпись metadata, ориентация массива карты p=1 и сохранение карты.

Численная проверка не доказывает качество QAOA для произвольной задачи или параметров. Точный перебор использует float64. Пределы размера — защитные ограничения, а не измеренная гарантия быстродействия.

## Учебные сценарии

`01_quickstart.ipynb`: 8 кодовых ячеек, 5 реальных изображений. `02_current_api_guide.ipynb`: 14 кодовых ячеек, 6 реальных изображений. В обоих выполнены ячейки сверху вниз в отдельных чистых IPython-процессах, сохранены выводы, проверены assert и структура nbformat. Дополнительно создан HTML-просмотр через nbconvert.

В этой среде запрещено создание локальных TCP/IPC-сокетов, поэтому обычное Jupyter-ядро через nbclient запустить не удалось. Проверка не подтверждает работу Jupyter-сервера в этой среде; она подтверждает последовательное выполнение самих ячеек в IPython и научный сценарий на установленном wheel. При локальной установке пользователь запускает ноутбук стандартным Jupyter.

HTML-просмотры сформированы nbconvert. Браузерная проверка их вёрстки не выполнена: Chromium также не запускается из-за запрета локальных сокетов. Вручную просмотрены сами PNG-изображения, встроенные в ноутбуки. Для математических формул HTML-просмотра могут потребоваться сетевые ресурсы MathJax; автономный интерактивный HTML относится к следующим этапам.

Графики просмотрены отдельно после выполнения. При визуальной проверке обнаружено наложение заголовка и статистики графа; отступ исправлен, изображения пересозданы. Проверьте свои длинные пользовательские подписи и размеры отдельно.

## Среда и ограничения

Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0, Matplotlib 3.10.8, Seaborn 0.13.2; Linux. Полный машинный список основных версий находится в `validation_environment.json`.

Проверенный текстовый движок — MathText с Computer Modern. Системный TeX не имеет рабочего latex.fmt; успешный LaTeX-рендер не подтверждён. NVIDIA, GPU-профили установки, Windows/macOS, старшие/младшие заявленные версии Python и файловые системы без hard links не проверялись.

RQAOA, LS, QAOA-in-QAOA, GW, Laboratory, параллельные пулы, профилировщик, общий запуск серий, контрольные точки и интерактивный HTML пока не реализованы. Следовательно, их корректность и производительность эта сборка не подтверждает. Формальная сертификация ASD-STE100 не выполнялась.
