RQAOA on CPU¶

Version 0.1.0rc2. This notebook walks through the complete first RQAOA scenario: small weighted graph → JSON configuration → QAOA training and physical correlations → pair selection → exact reduction → exact remainder → reconstruction → energy check → plots → saving and re-analysis.

The energy convention is E = -C. RQAOA is a heuristic. Exactly solving the remainder does not prove the global optimum of the original problem. The full state vector limits the graph size; this implementation does not scale to 1000 vertices.

2. RQAOA configuration¶

The configuration is read from JSON. finish_at=2 ends the loop with an exact solution of the two-vertex remainder. max_steps=4 shortens the tutorial run; the source still trains QAOA and returns physical correlations. Depth is p=1, angle order is gamma_0, beta_0.

3. Checking the complete solution and the energy¶

The dictionary must contain every source vertex exactly once. The cut value is recomputed by direct summation on the source graph. The reduction invariant is checked separately: C_original = b + C_reduced.

5. Reduction table¶

Each row refers to a merge performed after the correlations were obtained. selected_weight is the current weight of the pair, fixed_energy is the contribution after fixing, expected_fixed_energy is the expected contribution before fixing. score is a separate selection quantity, not a correlation.

10. Shot mode and a strict budget¶

In shot mode the training criterion and the correlations are estimated from samples. One correlation sample yields all pairs; training and correlation counters are kept separate. The remainder after two reductions is solved exactly and consumes no shots.

In [11]:
shots_config = deepcopy(config)
shots_config['parameters'] = {'finish_at': 4, 'max_reductions': 2}
shots_config['correlation_source']['estimation'] = {'mode': 'shots', 'shots_per_evaluation': 64}
shots_config['correlation_source']['correlations'] = {'mode': 'shots', 'shots': 512}
shots_config['correlation_source']['optimizer']['parameters']['max_steps'] = 2
shots_config['limits'] = {'shots_total': 20000}
shots = SolverFactory.from_config(shots_config)
shots_solution = shots.solve(graph)
print('Status:', shots.status, 'Reason:', shots.termination_reason)
print('Source:', shots.solution_source, 'Reductions:', shots.reductions_completed)
print('Shots:', shots.resources['shots_used'])
assert set(shots_solution) == set(graph.nodes)
assert shots.resources['shots_used'] <= 20000
assert shots.resources['readout_shots'] == 0

11. Stopping on a zero budget¶

A limit below the mandatory correlation sample does not start a measurement. A complete deterministic solution all_plus_reduced_fallback is returned; the status is stopped and the reason is shot_budget. This is not an exact solution of a large remainder and not a proof of optimality.

In [12]:
stop_config = deepcopy(shots_config)
stop_config['parameters'] = {'finish_at': 2, 'max_reductions': None}
stop_config['limits'] = {'shots_total': 0}
stopped = SolverFactory.from_config(stop_config)
stopped_solution = stopped.solve(graph)
print('Status:', stopped.status, 'Reason:', stopped.termination_reason)
print('Source:', stopped.solution_source, 'Shots:', stopped.resources['shots_used'])
assert stopped.status == 'stopped'
assert stopped.termination_reason == 'shot_budget'
assert stopped.solution_source == 'all_plus_reduced_fallback'
assert stopped.resources['shots_used'] == 0
assert set(stopped_solution) == set(graph.nodes)
