# Карта архитектуры и состояния переноса

**Версия:** 2 ноября 2026 года.
**База:** `QA_max_cut_lib 0.1.0a8`.
**Архитектура:** `docs/reference/MaxCut_Library_Architecture_RU.md`.

Документ фиксирует, как требования архитектуры ложатся на текущий код и что
ещё не реализовано. Он не заменяет инструкции этапов и не объявляет будущие
возможности готовыми.

## 1. Слои и правила зависимостей

| Слой | Модули | Правило |
|---|---|---|
| Core | `core.graph`, `core.records`, `core.saving`, `core.factory` | Общие типы, результат, сериализация, сборка. Не зависит от алгоритмов. |
| Solvers | `solvers.base`, CPU/GPU QAOA, RQAOA/LS, QAOA-in-QAOA, GW/SA, `RefinedSolver` | Полные алгоритмы и их вычислительные компоненты. Могут использовать Core и численные функции Tools. |
| Generators | `generators.graphs` | Рецепты графов, подграфы, разбиения. Не зависит от солверов. |
| Tools | `tools.numerics`, `tools.plotting`, `tools.reporting`, `tools.landscape`, `tools.demo` | Численные функции, анализ, визуализация, отчёты, демонстрации. Численные функции не импортируют графику и солверы. |
| Laboratory | `laboratory` | Экспериментальные сборки. Может использовать все слои; базовые слои не импортируют Laboratory. |

Текущая зависимость `core.saving -> core.records` нормальна. `solvers.base`
импортирует `core.saving` для автоматического экспорта; при развитии протокола
`save` это место нужно заменить на общий сервис без циклических импортов.

## 3. Чего ещё нет

### 3.1. Ядро запуска и результатов

- Нет `RunState` как отдельного объекта, достаточного для продолжения.
- Нет `RunContext` с бюджетом, случайностью, сбором данных и событиями.
- Нет `ParallelContext` общего назначения; `num_treads>1` реализован в
  `LSRQAOACPU`, `QAOAInQAOACPU`; SA использует CPU-пул, GPU-композиции — одного владельца.
- Нет контрольных точек и `resume()`.
- Нет явного разделения «описание алгоритма / состояние запуска /
  вычислительные компоненты»: `BaseSolver` хранит конфигурацию и последнюю
  запись, но состояние запуска живёт в локальных переменных `_run`.
- При ошибке предварительной проверки `_validate` запись `failed` не создаётся;
  архитектура требует доступную частичную запись при неудачном запуске.
- Нет реестра результатных полей с типами, единицами и правилами
  сериализации; `optional_fields` — временный список.

### 3.2. Солверы

- Нет D-Wave quantum annealer; классический SA реализован.
- LS-RQAOA есть в базовой версии; нет D_RQAOA, DLS_RQAOA, полей, частичных
  обновлений и Meta-LS.
- Базовый QAOA-in-QAOA и иерархия локальных задач реализованы без CE/полей.
- Нет Warm Start, полей, CE/обновляемого окружения и распределённых вариантов; базовый `ExactBlockRefiner` есть.
- Аналитический оцениватель p=1 и локальный аналитический источник есть.
- Базовый источник корреляций и селектор для RQAOA есть; LS использует
  индуцированные локальные задачи и параллельные процессы.
- `ExactBlockRefiner` и `RefinedSolver` реализованы; общие Benchmark/Profiler остаются отдельными.
- GPU QAOA/семплер и GPU-композиции реализованы; multi-GPU не входит.

### 3.3. Генераторы

- Только три простых генератора топологии и три типа весов.
- Нет исследовательских генераторов (Hebbian, Wishart, WPE, нелокальность).
- Нет плотных подграфов, расширения узлов/рёбер, сканирования, разбиений
  специального вида.

### 3.4. Tools

- Нет гистограмм больших распределений в виде столбцов на плоскости.
- Нет интерактивных 3D-ландшафтов и автономного HTML для них.
- Для RQAOA и LS-RQAOA есть траектории параметров, веса и энергетические
  кривые, покрытие пар и автономный 3D HTML; нет общего профилировщика.
- Нет единого LaTeX-стиля для всех интерактивных представлений.
- Нет `LandscapeScanner` как отдельного объекта с продолжением.
- Нет профилировщика параллелизма и кривых Амдала/Карпа–Флатта.
- Нет общего `ExperimentRunner`, плана испытаний и эталонной политики.
- Нет полного форматтера событий и цветовой темы для вложенных вызовов.

### 3.5. Laboratory

- Пакет пуст: `IMPLEMENTED_VARIANTS = ()`.
- Нет карточек исторических вариантов и именованных сборок.

### 3.6. Документация и качество

- `ASD-STE100` не сертифицирован; тексты написаны простым техническим
  английским, но формальная проверка не выполнялась.
- Нет матрицы «публичный объект → страница API → математическое описание →
  пример».
- Нет тематических ноутбуков 01–09 из архитектуры.
- Нет проверки кириллицы в LaTeX-режиме (MathText проверен).
- Нет лицензии и публикации пакета.

## 5. Точки расширения, которые нужно ввести

Предлагаемая последовательность не является планом этапов; она показывает
зависимости между будущими компонентами.

1. **Контракты Core.** `RunState`, `RunContext`, `ShotBudget`, `RunRecord`
   с реестром полей, `MaxCutSolver` как явный протокол.
2. **Оцениватель QAOA.** Отделить `QAOAEvaluatorCPU` от оптимизации; ввести
   сведения о представлении состояния и покрытии корреляций.
3. **Редуктор.** `IsingProblem`, `SpinConstraint`, `ReductionState` и
   `GraphReducer` готовы. Осталось добавить `PairSelector`, агрегированную
   `ReductionHistory` и связь с будущими источниками корреляций.
4. **RQAOA.** Готов базовый CPU-координатор с statevector- и аналитическим
   источником p=1. Следующий шаг — LS-подграфы; непрерывная оптимизация gamma
   не входит в текущий объём.
5. **LS-RQAOA.** Базовая версия с построителями, локальными задачами,
   покрытием, процессами и общим бюджетом готова. Следующие варианты —
   отдельные математические стратегии, не скрытые ветки базового LS.
6. **QAOA-in-QAOA.** Дерево локальных задач и обмен оценками.
7. **Tools.** Единый визуализатор, HTML, траектории, энергетические кривые.
8. **Серии.** `BenchmarkSpec`, `ExperimentRunner`, эталоны, resume.
9. **Профилировщик.** Сетка конфигураций, измерения, Амдал/Карп–Флатт.
10. **GPU.** Отдельные реализации и численная сверка с CPU.

## 6. Проверки, которые нельзя терять

- Полнота словаря решения и его разреза на исходном графе.
- Независимость ранее выданных `RunRecord` от нового `solve`.
- Строгий бюджет шотов на всех уровнях.
- Восстановление исходных номеров после редукций.
- Инвариант `C_original = b + C_reduced`.
- Единая энергетическая конвенция `E = -C`.
- Различие физической корреляции и score выбора пары.
- Отсутствие побочных файлов без `save`.
- Отсутствие запуска вычислений при импорте.
- Отсутствие скрытой подмены GPU на CPU.
- Соответствие `result` и прямых атрибутов одному источнику данных.

## 7. Что считать готовностью этапа

1. Новые возможности описаны в docstrings и документации.
2. Есть демонстрационный запуск модуля, если это солвер.
3. Есть независимая проверка на малой задаче.
4. Полный набор тестов проходит.
5. Обновлены `MIGRATION_STATUS.md` и карта покрытия.
6. Сделан отдельный git-коммит.
