# NVIDIA GPU QAOA

Версия `0.1.0a7` сохраняет GPU-путь через CuPy и добавляет GPU-вариант
QAOA-in-QAOA. CPU-солверы и загрузка сохранённых результатов не требуют CUDA
или CuPy.

## 1. Окружения

CPU и GPU проверяются в разных окружениях. В одном окружении должен быть
установлен один CuPy-пакет: `gpu-cu12` или `gpu-cu13`. Совместимый драйвер
NVIDIA обязателен; установка `cu13` не делает старую карту совместимой.

Проверенная локальная карта этой сборки:

| Поле | Значение |
|---|---|
| Устройство | NVIDIA GeForce RTX 3050 Laptop GPU |
| Compute capability | 8.6 |
| VRAM | 4 GiB (около 3.2–3.4 GiB свободно во время тестов) |
| Драйвер | 591.74 |
| CUDA runtime процесса | 13020 |
| CuPy | 14.2.0 |
| Python | 3.12.14 |

RTX 5060 Laptop в задании является ориентиром, но не измеренным устройством
этой машины. V100, RTX 5060 и другие карты не объявляются проверенными без
отдельного запуска.

## 2. Представления

`representation="full"` хранит физический `psi` длины `2**N`.
`representation="spin_flip_pairs"` хранит `chi` длины `2**(N-1)`:

\[
|[r]\rangle=\frac{|r\rangle+|\bar r\rangle}{\sqrt2},\qquad
\chi_r=\sqrt2\psi_r,\qquad q_r=|\chi_r|^2.
\]

Последний бит `node_order[N-1]` представителя равен нулю. Восстановление:
`concatenate([chi, chi[::-1]])/sqrt(2)`. Масса пары `q_r` соответствует двум
физическим строкам, каждая с вероятностью `q_r/2`.

## 3. API

- `QAOAGPU` (`qaoa_gpu`) — полный солвер, словарь спинов, readout и
  `state_representation`.
- `QAOAGPUCorrelationSource` (`qaoa_statevector_gpu`) — обучение и физические
  ZZ-корреляции для RQAOA/LS.
- `RQAOAGPU` (`rqaoa_gpu`) — общий RQAOA-координатор с GPU-источником.
- `LSRQAOAGPU` (`ls_rqaoa_gpu`) — LS с `execution.backend="gpu_owner"`;
  локальные задачи обслуживаются последовательно одним устройством.

Все солверы используют общий `RunRecord`; GPU-массивы при сборе преобразуются
в переносимые NumPy-массивы. `state_representation` явно сообщает тип
хранения, нормировку, `node_order`, правило представителя и смысл масс.

## 4. Критерии, градиенты, шоты

Все пять критериев считаются на устройстве по `C(r)` и `q_r` для pair-режима.
Exact Mean Cut поддерживает `gradient.type="adjoint"` с обратным проходом;
центральные разности доступны для всех критериев. Adjoint не применяется к
CVaR, Gibbs, Best-of-K, Threshold Probability или shots. Каждая полная
итерация центральных разностей имеет `4p+1` оценок; adjoint не выдаётся за
такое число экспериментальных оценок.

Семплер выполняет CDF+searchsorted на GPU. В pair-режиме сначала выбирается
`r` по `q`, затем независимо ориентация; обе физические строки возвращаются.
Шотовый бюджет проверяется координатором до измерения; readout резервируется
до обучения.

## 5. Память

Preflight учитывает состояние, диагональ, массы/вероятности и временный буфер,
свободную память устройства, fraction и reserve. Он не считает чужой CuPy pool
эксклюзивным и не гарантирует отсутствие OOM при внешних потребителях.
`max_vertices` — верхний пользовательский предел, а не обещание размещения.
Для 8 GiB нельзя обещать произвольный N=30 во всех dtype и критериях.

При OOM или отсутствии CuPy/устройства GPU-путь завершается ясной ошибкой и не
переключается скрыто на NumPy. CPU-солверы остаются доступны.

## 6. Ограничения

Не реализованы локальные поля, warm-start, другой миксер, multi-GPU,
распределённый запуск, CUDA Graphs, Walsh-плитки и batch>1. Прямой mixer
`pairwise` является проверенным вариантом; ускоренные варианты требуют
отдельной проверки. GPU-LS не создаёт CUDA-контекст в нескольких процессах.
